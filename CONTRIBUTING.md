# Contributing to Lpdf

Lpdf is not open contribution: we don't accept pull requests, in any lpdfio
repository. Codesense writes every change itself.

## Report a bug

The most valuable contribution is a bug report with the smallest Lpdf XML that
reproduces it. The same XML shows the bug in every SDK and in the VS Code
extension, so it's the fastest way to a fix. We fix it and credit you in the
release notes.

All issues are tracked in one place,
[github.com/lpdfio/lpdf/issues](https://github.com/lpdfio/lpdf/issues/new/choose),
for the engine, the SDKs and the extension.

## Questions and ideas

Ask in [Discussions](https://github.com/lpdfio/lpdf/discussions) on
lpdfio/lpdf: Q&A for how-to questions, Ideas for suggestions.

## Please don't send code

If you have found a fix, describe it in the issue rather than posting a patch.
We write the fix ourselves, and code posted in an issue or discussion is read as
a description of the problem. Suggestions and other feedback are welcome under
the Feedback terms of the [Lpdf license](https://github.com/lpdfio/lpdf/blob/main/LICENSE).

## Security

Never report a vulnerability in a public issue. See the
[security policy](https://github.com/lpdfio/.github/blob/main/SECURITY.md).

## Paid support

Professional and Enterprise support is by email. See
[lpdf.io/support](https://lpdf.io/support).
